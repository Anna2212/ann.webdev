# annwebdev.com

Персональний сайт Анни Медвідь. Astro, статична збірка, хостинг на Netlify.

## Запуск локально

Потрібен Node 20 або новіший. Перевірити: `node -v`

```bash
npm install     # один раз
npm run dev     # відкриється http://localhost:4321
```

Сторінка оновлюється сама, щойно зберігаєш файл.

```bash
npm run build   # зібрати в dist/
npm run preview # подивитись зібрану версію
```

## Деплой

Netlify збирає сайт сам при кожному пуші в основну гілку. Налаштування вже
лежать у `netlify.toml`, у панелі нічого вписувати не треба.

Кожна гілка отримує свою прев'ю-адресу — зручно показати клієнту або перевірити
правку до того, як вона потрапить на бойовий сайт.

## Структура

```
src/
  data/site.ts        Контакти, меню, тексти кнопок — єдине джерело правди
  layouts/Base.astro  Шаблон сторінки: head, мета-теги, schema, шапка, футер
  components/         Logo, Header, Footer
  pages/              Кожен файл = сторінка сайту
  styles/global.css   Дизайн-токени і базові стилі
public/               Файли, що копіюються як є: фавікон, robots.txt
```

## Де що міняти

**Контакти, телефон, пошта, посилання на соцмережі** — `src/data/site.ts`.
Змінюєш в одному місці, міняється на всьому сайті.

**Пункти меню** — там само, масив `NAV`. Порядок у масиві = порядок у меню.

**Кольори, розміри шрифтів, відступи** — `src/styles/global.css`, блок `:root`
на початку файлу. Це всі токени з брендбуку.

**Текст на сторінці** — відповідний файл у `src/pages/`. Верхня частина файлу
між `---` це налаштування сторінки, нижня — сам вміст.

## Шрифти

Montserrat, Playfair Display Italic і Caveat лежать у проєкті локально, через
пакети `@fontsource`. Зовнішніх запитів до Google Fonts немає — це швидше і не

слова через клас `.accent`. У дрібному тексті курсивна антиква мажеться.

## Форма заявки

Заявку ловить **Netlify Forms**. Це важливо не заради зручності, а заради
надійності: заявка зберігається в Netlify навіть якщо JavaScript вимкнено або
серверна функція впала. Telegram і таблиця — надбудова, а не єдина точка відмови.

```
форма на сайті
  → Netlify зберігає заявку (Forms у панелі, є експорт у CSV)
  → подія submission-created запускає функцію
       → повідомлення в Telegram
       → рядок у Google Таблицю
  → на сторінці замість форми з’являється «Отримала»
```

### Що треба налаштувати, щоб приходили сповіщення

Без цих налаштувань форма все одно працює — заявки лежатимуть у Netlify в
розділі Forms. Але сповіщень не буде.

**1. Створити бота для сповіщень**

У Telegram знайти `@BotFather` → `/newbot` → придумати назву. У відповідь
прийде токен виду `1234567890:AAF...`. Це пароль від бота, нікому не показуй
і в код не встав.

**2. Дізнатись свій chat_id**

Написати створеному боту будь-що, потім відкрити в браузері:
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайти в відповіді
`"chat":{"id":123456789`. Це і є chat_id.

**3. Підключити таблицю**

Код і покрокова інструкція — у файлі `docs/apps-script.gs`.

**4. Завести змінні в Netlify**

Project configuration → Environment variables:

| Змінна | Значення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен від BotFather |
| `TELEGRAM_CHAT_ID` | твій chat_id |
| `SHEETS_WEBHOOK_URL` | адреса веб-застосунку Apps Script |

Після додавання змінних треба **перезапустити деплой** — Netlify підхоплює їх
тільки при збірці. Deploys → Trigger deploy → Deploy site.

### Важливо про безпеку

Токен бота й адреса таблиці живуть **тільки** у змінних середовища Netlify і
читаються всередині серверної функції. У код сторінки вони не потрапляють
ніколи. Якщо токен опиниться у фронтенді, будь-хто зможе вийняти його з коду
сторінки і писати від імені бота.

### Як перевірити, що працює

1. Відкрити сайт, заповнити форму, надіслати
2. На сторінці має з’явитись «Отримала» замість форми
3. У Netlify → Forms має з’явитись заявка
4. У Telegram має прийти повідомлення
5. У таблиці має з’явитись рядок

Якщо пункти 1–3 працюють, а 4–5 ні — справа у змінних середовища. Подивитись
логи: Netlify → Logs → Functions → `submission-created`.

### Захист від спаму

Поле-пастка, приховане від людей. Бот його заповнює, людина ні — Netlify такі
заявки відсіює сам. Капчу навмисно не ставила: вона знижує кількість реальних
заявок сильніше, ніж рятує від спаму.

Плюс обмеження: повторна відправка не частіше ніж раз на 30 секунд.

## Індексація закрита — тимчасово

Поки сайт живе на технічному домені Netlify, він закритий від пошукових систем.
Це щоб Google не проіндексував адресу виду `*.netlify.app` і не довелось потім
розгрібати дублі з майбутнім `annwebdev.com`.

**Що вмикає заборону, у двох місцях:**

1. `src/data/site.ts` — константа `ALLOW_INDEXING = false`. Через неї в кожну
   сторінку додається `<meta name="robots" content="noindex, nofollow">`
2. `netlify.toml` — заголовок `X-Robots-Tag: noindex, nofollow` для всіх адрес

Два рівні тому, що частина ботів читає заголовок, а частина мета-тег.

**Як зняти заборону, коли підключиш свій домен:**

1. У `src/data/site.ts` поставити `ALLOW_INDEXING = true`
2. У `netlify.toml` видалити перший блок `[[headers]]` — той, що з `X-Robots-Tag`
3. Запушити зміни
4. Перевірити: відкрити сайт, подивитись код сторінки — рядка з `noindex` бути
   не повинно

Зверни увагу: `robots.txt` навмисно **не** блокує ботів. Якщо заборонити їм
заходити, вони не побачать мета-тег і сторінка може все одно потрапити у видачу.
Правильна схема саме така: заходити дозволяємо, індексувати забороняємо.

## Технічна обв'язка

**`sitemap.xml`** генерується автоматично при збірці через `@astrojs/sitemap`.
Сторінка подяки і 404 у мапу не потрапляють. Нічого вручну оновлювати не треба —
додаєш сторінку, вона з'являється в мапі сама.

**`llms.txt`** у теці `public` — короткий опис сайту для AI-систем. Це не
офіційний стандарт, але частина систем його вже читає. Якщо міняєш послуги,
терміни чи умови — онови й цей файл, інакше факти розійдуться.

**`_redirects`** — правила Netlify. Зараз там тільки прибирання косої риски
наприкінці адрес, щоб `/poslugy/` і `/poslugy` не були двома різними сторінками.

**Схема schema.org** прописана на кожній сторінці: `Person`, `ProfessionalService`
і `WebSite` на головній, `Service` на послугах, `FAQPage` на FAQ,
`CreativeWork` плюс `BreadcrumbList` на кожному кейсі.

**Сторінка 404** віддається Netlify автоматично — файл `404.html` у корені
збірки, окремих налаштувань не потрібно.

## Що лишилось зробити

**Фотографії — готові.** Оброблені й підключені: обрізані під 4:5, переведені
в WebP, збережені у двох розмірах під звичайні й ретіна-екрани.

| Файл | Де стоїть |
|---|---|
| `stairs` | головна, перший екран |
| `process` | головна, блок «як я працюю» |
| `portrait` | головна, блок «коротко про мене» |
| `about` | про мене, головний портрет |
| `street` | про мене, особиста частина |
| `laptop-phone` | послуги, вступ |
| `contact` | контакти |
| `call`, `notebook`, `stairs-alt` | у запасі, поки не використані |

Компонент `Photo.astro` сам підставляє потрібний розмір і вмикає ліниве
завантаження для всього, крім першого фото на сторінці.

**Щоб замінити фото:** поклади файл у `public/images/` під тією ж назвою у двох
розмірах — `name.webp` (900px завширшки) і `name@2x.webp` (1400px), обидва в
пропорції 4:5.

**Скріни кейсів — досі заглушки.** Треба шість штук у пропорції 3:2, файли
`case-mporto`, `case-slidom`, `case-hr`, `case-kvity`, `case-thecash`,
`case-drivelive` у теці `public/images/`.

**OG-зображення** зараз SVG-заглушка. Краще замінити на JPG 1200×630 зі
справжнім фото.

**Фавікон у PNG.** Зараз є тільки SVG. Треба додати `icon-192.png`,
`icon-512.png` і `apple-touch-icon.png` — можна згенерувати з `favicon.svg`
будь-яким онлайн-сервісом.

індексації за інструкцією нижче.
